# NIGHTSHIFT — ChatGPT Work Order 02

**Owner:** ChatGPT research/specification workstream  
**Status:** Active; autonomous execution  
**Repository:** `MrPavian/Nightshift`, branch `main`  
**Boundary:** This work order does not authorize production implementation assigned to Claude.

## Mission

Reduce specification risk before Claude begins the first production implementation slice. Turn the existing research library and contracts into one consistent, dependency-ordered implementation path, then continue the research and design work needed for a distinctive, historically grounded graffiti lettering system.

## Responsibility split

### ChatGPT delivers
- Cross-document and machine-contract consistency audits.
- Source-grounded construction research and unresolved-evidence tracking.
- Per-glyph A–Z construction briefs and controlled variant proposals.
- Style grammar compatibility and application rules.
- Test fixtures, review rubrics, calibration plans and proof-sheet requirements.
- Small, verifiable Claude implementation tickets.
- Roadmap, indexes, decision records and changelog maintenance.
- Verification of repository updates and any implementation evidence returned by Claude.

### Claude delivers
- Production code and runtime architecture.
- Canonical model, vector geometry, topology validator and glyph registry.
- Integrated Three.js editor and stable-ID command interaction.
- Relationship solver, procedural generator, persistence and export.
- Executable automated tests, proof artifact generation and defect fixes.
- Implementation reports with test results and limitations.

## Work sequence

### W02.1 — Specification consistency audit (active)
- Compare the A/B/G/R/S glyph-specific specification with the master, data, parameter, geometry and construction-pipeline contracts.
- Check operation registry completeness, write sets, dependency invalidation and variant IDs.
- Identify contradictory topology assumptions, uncalibrated controls, premature maturity claims and fixture drift.
- Record findings with severity, affected files and recommended resolution.
- Correct only unambiguous documentation/contract defects; preserve open interpretation as an explicit gate.

**Exit:** audit report, resolved critical contradictions, linked references and verified commits.

### W02.2 — Claude implementation ticket decomposition
- Convert the agreed first slice into independently testable tickets: legacy import, canonical records, semantic overlays, topology validator, monochrome renderer, proof output.
- State inputs, outputs, dependencies, non-goals, acceptance tests and failure behavior per ticket.

**Exit:** one ordered Claude task packet that can be implemented without guessing.

### W02.3 — A–Z construction coverage plan
- Review the 26-letter structural matrix against the current A/B/G/R/S maturity.
- Prioritize letters by coverage value, identity risk and pair/word frequency.
- Specify semantic construction, protected negative spaces, likely component graph and candidate anchors per letter.
- Keep all unreviewed forms provisional and distinguish authored constructions from generic fallback shapes.

**Exit:** a staged alphabet authoring plan with explicit per-letter evidence and review status.

### W02.4 — Style grammar application and calibration plan
- Audit Bubble, Straight, Blockbuster and Wildstyle axes and their compatibility rules.
- Define which grammar combinations can be tested with the first authored subset.
- Specify monochrome structural comparisons before finish effects.
- Connect each exposed parameter to its owning subsystem, registered operation and calibration evidence.

**Exit:** first supported grammar-combination matrix and calibration backlog.

### W02.5 — Relationship and generator readiness
- Check that glyph anchors, relationship types, solver hard gates and procedural candidate generation agree.
- Identify what can safely ship in early solver phases versus what must wait for topology and visual review.
- Define a minimal generator vertical slice and reproducibility tests.

**Exit:** staged Claude tickets for safe adjacency, controlled overlap and four-concept generation.

### W02.6 — Ongoing source and archive research
- Expand contested/underrepresented historical areas where evidence materially changes construction or scene context.
- Keep item-level image rights/provenance.
- Coordinate the separate BLACKBOOK ARCHIVE roadmap without merging its content scope into the generator.

**Exit:** source-backed additions with citations, uncertainty notes and explicit product implications.

## Global quality gates

- No production feature is claimed from a specification alone.
- No arbitrary parameter bounds, metric coordinates or geometry tolerances.
- No semantic stroke order inferred from closed contours.
- Counters, apertures and channels remain distinct.
- No background-colour patches for negative space.
- No automatic glyph maturity promotion.
- No copying identifiable living artists' signatures or protected works.
- Historical fact, practitioner account, scholarly interpretation and NIGHTSHIFT design inference remain visibly separate.
- All new docs are cross-linked and repository writes are fetched and verified.
- Work continues without routine owner approval; stop only for genuine product-direction, access, rights or safety blockers.
